# 技能五子棋 AI

基于 Python 的技能五子棋项目，支持 AI 与随机策略对战、AI 自对战，以及通过 Tkinter 界面进行人机对战。除常规五子连珠外，每位玩家每局还可使用一次技能，封锁对手下一回合的一个落子位置。

本项目基于南京大学人工智能导论 Project 2「技能五子棋 AI」课程实验框架整理。`student.py` 包含当前策略实现，`agent.py`、`gomoku.py` 和 `human.py` 提供智能体接口、游戏环境与人机交互支持。

## 目录结构

```text
gomoku-ai/
├── README.md          # 项目说明与运行方法
├── requirements.txt   # Python 第三方依赖
├── .gitignore         # Git 忽略规则
├── agent.py           # 智能体基类与随机策略
├── gomoku.py          # 游戏规则、胜负判断和命令行入口
├── human.py           # Tkinter 人类玩家界面
└── student.py         # Search 智能体与策略实现
```

四个 Python 文件保留在同一目录，以兼容当前模块导入方式。

## 环境准备

建议使用 Python 3.10 或更新版本，需要 NumPy 和带 Tkinter 支持的 Python 环境。

在项目根目录执行：

```bash
python -m pip install -r requirements.txt
```

Tkinter 不通过本项目的 `requirements.txt` 安装。可使用 `python -c "import tkinter"` 检查是否可用；当前入口即使运行 AI 对战也会导入 `human.py`，因此同样需要 Tkinter。

## 快速开始

### AI 对战随机策略

```bash
python gomoku.py -m random
```

玩家 1 使用 `student.Search`，玩家 2 使用 `agent.Agent` 随机落子。

### 人机对战

```bash
python gomoku.py -m human
```

AI 为玩家 1，先手；人类为玩家 2，通过棋盘窗口点击落子。点击“释放技能”后，先选择封锁位置，再选择本回合落子位置。技能位置应选择没有棋子的交叉点，且不能与本回合落子位置相同。关闭等待落子的窗口视为认输。

### AI 自对战

```bash
python gomoku.py -m student
```

### 使用 15 × 15 棋盘

```bash
python gomoku.py -m human -s 15
```

命令行默认棋盘为 **11 × 11**，坐标从 `0` 开始。`create_board()` 函数本身的默认尺寸为 15，两者不同。

## 规则与接口

- 在横向、纵向或两条斜线上形成连续至少五枚己方棋子即获胜。
- 每位玩家每局可使用一次封锁技能，效果持续到对手下一回合结束。
- 非法落子判负；非法技能目标会消耗技能次数，但不会产生有效封锁。
- 引擎为 AI 设置每步 60 秒的等待超时；人类交互走独立流程。

智能体继承 `Agent`，通过 `make_move(board)` 返回：

```python
((row, col), None)                    # 仅落子
((row, col), (skill_row, skill_col))   # 落子并释放技能
```

棋盘编码：`0` 为空位，`1`、`2` 为双方棋子，`3`、`4` 为双方释放的技能标记。

## 当前策略

`student.Search.make_move()` 当前采用以下决策流程：

1. 在已有棋子周围两格范围内生成候选落点；空棋盘选择中心。
2. 优先选择能够立即获胜的落点。
3. 若对手下一步能获胜，优先占据该落点进行防守。
4. 对其余候选点计算“己方棋型评分 + 0.8 × 对手棋型评分”，选择得分最高的位置。
5. 未使用技能时，若检测到高分威胁且威胁位置不同于落子位置，则尝试封锁该位置。

棋型评分考虑四个方向上的连续棋子数量与两端开放情况。

**实现状态：** 文件中已包含 Minimax 与 Alpha-beta 剪枝函数，但 `make_move()` 尚未调用它们。因此当前运行策略属于启发式选点，不能将其描述为已经启用多层博弈搜索。`max_depth = 10` 不代表实际进行了十层搜索；候选数量限制也只作用于尚未接入的搜索路径。

## 当前局限与可改进方向

- 可将现有 Minimax 接入落子决策，并增加可控的搜索深度或时间预算。
- 现有 Minimax 未模拟技能释放及封锁到期，接入前需补充相关状态处理。
- 当前评分主要识别连续棋型，尚未完整覆盖跳活三等非连续棋型。
- 引擎使用线程等待超时，不能强制终止正在执行的策略线程，因此不应视为严格的运行时隔离。
- 当前仓库未附自动化测试套件或系统性胜率评测，暂不提供棋力或性能保证。
